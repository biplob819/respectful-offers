# E4.1 acceptance criteria

**EVK-01** — `offers metrics` turns `results/kkbox/summary.json` into a `metrics-1` file that `validate_metrics1` accepts; every interval in the summary appears with identical numbers; violations appear per rule with the policy's `respectful` flag; `simulated` is true; no member id appears; the validator refuses each planted defect (unknown top-level key, bad unit, count that is a float or negative, rate outside [0, 1], interval without `ci_method`, value outside its interval, duplicate name+labels, nested label, member-shaped value); re-exporting a summary with every number scaled changes every exported number; the committed `results/kkbox/metrics.json` equals a fresh export (`--check` exits 1 on drift).
**EVK-02** — `configs/gates.yaml` holds the OWNER D-52 gates; `scripts/gate.py` on the committed metrics exits 0 with the disparity warn listed; a planted R1 violation on a respectful policy exits 1, the same on the status quo does not; a claim whose lower bound drops below 0 exits 1; a gate matching nothing, an unknown op, or `bound` on a metric without an interval exits 2; `gate.json` is written on every exit path and carries `simulated: true`; the committed `results/kkbox/gate.json` is current; CI runs both checks.
